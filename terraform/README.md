# 3-Tier App 

A classic web / application / data topology, ready to plan and apply.

```
                          Internet
                             │
                    ┌────────▼─────────┐
   snet-gateway     │ Application GW   │   :80
                    └────────┬─────────┘
                             │
                    ┌────────▼─────────┐
   snet-app         │  VMSS (2-4 VMs)  │   private, NAT egress
                    └────────┬─────────┘
                             │  :5432
                    ┌────────▼─────────┐
   snet-data        │ PostgreSQL Flex  │   VNet-injected, no public endpoint
                    └──────────────────┘
```

## What it creates

**Network** (`modules/network`) — a virtual network with three subnets: a
dedicated gateway subnet, a private app subnet (NSG-protected, NAT gateway for
outbound), and a data subnet delegated to PostgreSQL Flexible Server. Also the
private DNS zone and VNet link the database needs.

**Web tier** (`modules/app_gateway`) — an Application Gateway v2 with a static
public IP, an HTTP listener, a backend pool the scale set registers into, and a
health probe on `var.health_check_path`.

**Application tier** (`modules/app_tier`) — a Linux VM scale set with no public
IPs, SSH-key-only access, a system-assigned managed identity, and a CPU-based
autoscale rule.

**Data tier** (`modules/database`) — a PostgreSQL Flexible Server injected into
the delegated subnet with `public_network_access_enabled = false`, plus a Key
Vault holding the generated admin password.

## Security posture

- The Application Gateway's public IP is the only internet-facing address.
- The app subnet NSG allows inbound only from the gateway subnet plus the
  `GatewayManager` service tag (which Application Gateway v2 health probes
  require), and denies everything else.
- The database has no public endpoint and no firewall rules — it is reachable
  only from inside the VNet, via the private DNS zone.
- Password authentication is disabled on the VMs; `var.ssh_public_key` is
  required.
- The database password is generated by `random_password` and written to Key
  Vault (RBAC-authorized). **It is still in Terraform state** — Azure has no
  service-managed password equivalent to RDS, so keep state in a remote backend
  with restricted access.

## Getting started

```bash
cd terraform
cp terraform.tfvars.example terraform.tfvars   # then edit
terraform init
terraform validate
terraform plan
terraform apply
```

Four inputs have no default and must be set: `subscription_id`, `tenant_id`,
`ssh_public_key`, and — practically — `location`.

```bash
az account show --query "{sub:id, tenant:tenantId}"
cat ~/.ssh/id_rsa.pub
```

Per-environment settings:

```bash
cp environments/prod.tfvars.example environments/prod.tfvars
terraform apply -var-file=environments/prod.tfvars
```

## Before production

| Setting | Change to | Why |
|---|---|---|
| `gateway_sku_name` | `WAF_v2` | Managed OWASP rules in front of the app |
| `postgres_sku_name` | `GP_Standard_D2s_v3` | Burstable can't do zone-redundant HA |
| `postgres_high_availability` | `true` | Automatic database failover |
| `postgres_backup_retention_days` | `35` | Longer recovery window |
| `purge_protection_enabled` (database module) | `true` | Stops permanent secret deletion — **irreversible once set** |
| Remote state | Uncomment `backend "azurerm"` in `providers.tf` | The state file contains the DB password |
| TLS | Add a certificate and an HTTPS listener | Port 80 only is not enough |
| `upgrade_mode` (app_tier module) | `Rolling` | Needs an Application Health extension first |

`environments/prod.tfvars.example` already reflects most of these.

## Notes

- **The data subnet is delegated** to `Microsoft.DBforPostgreSQL/flexibleServers`
  and therefore cannot host anything else. Add a fourth subnet if you need more
  private resources.
- **The gateway subnet is dedicated** and deliberately has no NSG — Application
  Gateway rejects restrictive rules on its own subnet.
- Key Vault and PostgreSQL server names are globally unique, so both carry the
  `random_string.suffix` value. The vault name is truncated to Azure's 24-char
  limit.
- `module.database` declares `depends_on = [module.network]` because the server
  needs the subnet delegation and the private DNS zone link in place first, and
  neither is expressible as an attribute reference.
- `ignore_changes = [zone]` on the server prevents a forced replacement on every
  plan — Azure picks the availability zone at create time.

## Cost

Roughly, in `eastus` at defaults (dev): Application Gateway Standard_v2
(~$180/mo — the dominant cost, it bills per instance-hour plus capacity units),
2 × `Standard_B2s` (~$60/mo), NAT gateway (~$32/mo plus data), and
`B_Standard_B1ms` PostgreSQL (~$15/mo). For a cheap dev environment, swapping
the Application Gateway for a Standard Load Balancer saves the most.
